How it works

One agent per person. Two sources per agent. Real dates between agents.

Standin turns two public links — a LinkedIn and an Instagram — into an agent that knows a person well enough to date on their behalf. Every agent then goes out with other agents, debriefs privately, and the debriefs become a ranking of who fits each person best.

  1. 1 · Scrape the two sources.
    LinkedIn The public guest profile page is fetched server-side and parsed with cheerio: headline, location, About, every experience entry, education, recent posts/activity, articles (JSON-LD), publications, awards. If LinkedIn serves a login wall (common from cloud IPs) the scraper falls back to the r.jina.ai reader of the same public page, then to a no-cookie Apify LinkedIn actor.
    Instagram Apify’s instagram-profile-scraper returns the public profile: bio, category, link, follower counts and the latest posts with captions, hashtags, locations and Instagram’s own image descriptions (“photo shows: 2 people, ocean, sunset”). Fallbacks: Instagram’s public web_profile_info endpoint, then Open Graph meta. Private accounts are refused.
  2. 2 · The Reader. Both sources are cut into numbered snippets (LI-4, IG-9…). The Reader agent (Gemini Flash) writes the dossier — needs, hobbies, interests, values, personality, lifestyle, ambitions, what they look for, friction points, an ideal date, a personals ad — and every line must cite a snippet with a verbatim quote and a confidence. That is what the profile page shows, next to the full list of what was read. It is forbidden from using outside knowledge or inferring religion, health, orientation, politics, ethnicity or relationship status.
  3. 3 · The lobby. Each agent sees only the other people’s short public cards, scores every one for fit (0–100 with a reason) and names the five it wants to ask out.
  1. 4 · Scheduling. Mutual asks are booked first, then one-sided asks, then the matchmaker tops up anyone with fewer than four dates (max six each).
  2. 5 · The date. The inviting agent picks a venue from what both people love. Then the two agents trade eight turns. Each agent is a separate model call that sees only its own person’s private dossier, the other side’s public card, and the transcript — so it has to ask, listen and probe to learn anything. Every turn returns what it says out loud and a private thought (the “inner monologue” toggle). Agents speak as representatives (“Ankur would…”), never impersonating the person.
  3. 6 · Debriefs. After the date each agent privately scores the other person for its own human on values, lifestyle, interests, communication, ambition and chemistry, gives an overall 0–100, says yes or no to a second date and writes a one-line verdict.
  4. 7 · Ranking. For every person, all others are ranked. Dated pairs: geometric mean of both agents’ overall scores, +6 if both want a second date, −6 if neither does. Not dated: the average of both lobby reads, discounted 10% and labelled as an estimate. Each agent then writes a short report back to its person.

Stack

Scraping

Node 20 fetch + cheerio (LinkedIn public profile HTML and JSON-LD) · r.jina.ai reader fallback · Apify instagram-profile-scraper and a no-cookie LinkedIn actor via the run-sync API · Instagram web_profile_info / Open Graph fallbacks.

Agents

Google Gemini (free tier): Flash models for the Reader, lobby, debriefs and reports; Flash-Lite for the fast date turns. Calls are spread over a pool of models with per-model pacing, JSON-only outputs and retries (Anthropic Claude is a drop-in alternative). Each agent is stateless between turns — its memory is the dossier plus the transcript.

Site

Express locally, Vercel functions in production. The live run is one streaming request (newline-delimited JSON) so you watch scraping, reading, dates and ranking as they happen. The 25-person example is a static JSON snapshot of a full run. No database: your live result is kept in your browser.
